## 二、项目背景与参考依据

### 2.1 背景

- `docs/MIGRATION_PAPER_1.21.md` 记录 ThePitUltimate 向 1.21.x 的适配：目标 Paper 1.21.8、Java 21、物品数据由 NBT 迁至 PDC、`AttributeModifiers` 重写、枚举与粒子 / 全息 / 聊天层改造。`README.md` 中的 1.8.8 为 master 基线，迁移在 `feat/paper-1.21.8` 分支推进。
- 近期提交已加入挂机池自动精通、时空商人、垃圾桶命令与配置化、实体硬币兑换、稀有附魔「我拒绝」等新功能。本次在既有神话之剑 / 神话之弓 / 神话之甲体系上新增重锤品类「神话之锤」。
- `IMythicItem` 以 `tier` 1 / 2 / 3 标记物品阶（显示层为 I / II / III 阶），附魔按 `tier` 分池；物品带 `live / maxLive` 生命值并按 60% / 30% 阈值变色；生命归零即不可用，可由凋灵工艺、神话工匠包、暗聚块等机制修复。
- 神话物品本体由击杀掉落（`custom.yml:218-224` 的 `mythicDropChance` 0.01 / 0.012）；**神话之井只是附魔入口**（`MythicEnchantingTable` + `MythicWellMenu` + `EnchantButton`），不是物品产出源。

### 2.2 参考依据

| 维度 | 仓库依据 | 本设计沿用方式 |

### 2.3 设计约束

- 编号 1–100 连续且唯一；名称、效果、描述均为新写，不复制仓库现有附魔，也不含任何原版附魔（锋利、保护、耐久、力量、击退、火焰附加、抢夺、时运、效率、无限、修补、经验修补、穿透、忠诚、穿刺、引雷、荆棘等）。使用原生重锤后，其专属原版附魔（致密 / 破甲 / 风爆）同样禁止。
- 类别标签仅 `普通`、`稀有!`、`<font color="green"><b>季节性!</b></font>` 三种；后者以绿色加粗呈现（内联 HTML，兼容常见 Markdown 预览；剥离颜色时退化为纯文本 `季节性!`）。三类数量为 70 / 20 / 10。
- 每条含 7 个字段：编号、中文名称、类别标签、物品阶适配、效果概述、与生命属性的适配说明、平衡定位。物品阶适配给出 tier 1 / 2 / 3 三档数值或明确限定 tier。
- 「回复生命值」只作用于玩家血量；「回复 `live`」才延长物品可用次数；护盾值与生命吸收是另外两套独立资源。
- 开放 = 可从神话之井获得且玩家可正常使用；未开放 = 既不可获得也不可使用。开放表独立于清单，只列编号。

### 3.2 「重锤」口径

- **物品本体就是重锤**：`Material.MACE`，不是「用斧头改显示名」。1.21 原生重锤自带攻击冷却 0.6、下落攻击（猛击）与三种专属附魔，本设计在这个物品上叠加神话体系。
- **显示名定稿为「神话之锤」**，品类 / lore 标注「重锤」。
- `ItemTypes.java:44-46` 的 `isAxe` 按 `_AXE` 后缀判定，`MACE` **不匹配**；同时 `MACE` 也不落入 `isSword` / `isBow` / `isArmor` 任何分支，`AbstractEnchantment#canApply` 的材质分支会全部返回 `false`——**必须由新增的 `isMythicHammer`（PDC `mythic_hammer`）分支接管**，否则锤一条附魔都拿不到。
- 普通 `MACE` 物品与普通斧都不能吃这 100 条（无 PDC `ench`、被 `canApply` 拦截）。

## 四、附魔体系架构

### 4.1 稀有度枚举

- `EnchantmentRarity.java` 实际 **21 个**枚举值；`RarityType` 只有 NORMAL / RARE / LIMITED 三值。枚举内原本没有季节性类别与绿色前缀，限时前缀是 `OP` 的红色 `&c限时! `。
- **新增 `SEASONAL("&a季节性! ", RarityType.LIMITED, 10)`，不复用 `OP`**（语义为季度轮换，与运营限时不同）。
- `itemColor = 10`：唯一消费点是 `menu/admin/item/button/EnchantButton.java:62-65` 的 `WHITE_WOOL` + `.durability()`；`LegacyColor.java:13-16, 32-40` 接受 0–15，索引 10 = `PURPLE` → `PURPLE_WOOL`。已占用 `{0,1,2,3,4,5,7,8,9,14,15}`，10 未占用且与 NORMAL(5 → LIME)、RARE(2 → MAGENTA) 三色互异。6 保留给后续扩展。
- 映射：普通 → `NORMAL` 系列（含 `DARK_NORMAL` / `SEWER_NORMAL` / `FISH_NORMAL` 等按场景），稀有! → `RARE` 系列，季节性! → `SEASONAL`。
- **文档标签 ≠ 代码枚举**：三类标签是输出约束；稀有度由 `EnchantmentRarity` 决定，`custom.yml rate` 只控制按阶 / 场景的产出权重，不含 `rare` 池或「限时池」。

### 4.2 神话之井抽取与 `SEASONAL` 挂载

| 步骤 | 定稿 |
| --- | --- |
| 0 | **`SEASONAL` 不得实现 `ILimit`**。`EnchantButton.java:836-838` 的 `isBlackList` = `instanceof ILimit`，实现后会被从所有候选剔除，永远抽不到 |
| 1 | 在 `EnchantButton.java:319` 之后、`:326` 之前构建**独立** `seasonalResults`：`list` 中 `rarity == SEASONAL` 且编号 ∈ 当前季度开放集合且通过 `isBlackList`。**不并入 `results` / `rareResults`**，避免被 `:332-345` 的 color 分支覆盖，也不污染 `helpMeToChooseOne` 的既有掉率分布 |
| 2 | 新增配置 `seasonal-chance`：物品阶 tier 1 / 2 / 3 = **0% / 5% / 10%**。在 `:350-400` switch 抽取**完成之后**做一次覆盖式判定，保持既有随机序列不变 |
| 3 | 命中且 `seasonalResults` 非空：用 `removeExistingEnchantments`（`:509-511`）去掉已持有项，随机取一条写入，附魔等级 `level` 按本次设计取 `level = tier`（1 / 2 / 3；本设计选择，非仓库既有规则），走 `:456` 同级的稀有广播 |
| 4 | 卷轴：新增 `getBookSeasonalResults`（与 `getBookRareResults:475-495` 同构），只在当前季度开放集合内产出；跨季持有卷轴按 §4.5 失效 |
| 5 | 互斥组 M1 / M2 的过滤挂在 `:347-348` 的候选过滤处，与 `isBlackList` 并列 |

- 权重不进 `custom.yml rate`，不改现有 NORMAL / RARE 的概率分布。

| `streak` | 连杀计数 | 复用 | `PitStreakKillChangeEvent` |

**C2 秒 ↔ 百分比换算（统一中间量 = 攻速百分比 p）**

| 条目 | 原始数值 | 折算 p |
| --- | --- | --- |

| 95 灼砧 | +6% / +9% / +12% | 直接为 p，不换算 |

### 4.5 季节开放判定

- **服务端真实日期自动判定**，不读客户端时间；时区固定 `Asia/Shanghai`，在配置中显式声明。
- 边界：按自然月，每季度首日 00:00:00 生效、末日 23:59:59 后失效；纯函数「当前月份 → 季度 → 开放编号集合」，不依赖重启。
- 手动开关：`seasonal-override`（`auto / force-open / force-close` + 编号白名单），仅用于测试与活动，生产默认 `auto`。
- 两侧（获得侧过滤、使用侧短路）共用同一个 `isSeasonOpen(enchant)`，避免判定漂移。

**未开放处理**

| 项 | 裁定 |
| --- | --- |
| 词条本身 | **保留但置灰**，不隐藏、不删除、不改写 PDC 数据 |
| 效果 | 在附魔触发链入口统一短路，不进入伤害 / 状态 / 结算 |

## 五、术语与数值口径

### 5.1 核心术语

| 术语 | 定义 | 判定口径 | 1.21 实现映射 | 禁止口径 |
| --- | --- | --- | --- | --- |
| 满蓄力 | 攻击冷却进度达到 1.0 | 进度 `>= 1.0` | 攻击冷却进度读取（落地时对照 Paper 1.21.8 javadoc 复核） | 不得用「按住右键时长」实现 |
| 重击 | 满蓄力状态下的一次近战命中 | 满蓄力 + `EntityDamageByEntityEvent` 且主手为锤 | 伤害事件 + 冷却进度 | 不与「暴击」（跳跃下落）、原版「猛击」混用 |
| 命中 | 一次近战攻击判定到至少一个实体 | `EntityDamageByEntityEvent`，主手 `mythic_hammer` | 统一 `CombatListener` 伤害管线 | 不含对方块 / 盔甲架 / 自身 |
| 挥空 | 一次攻击发起但未命中任何实体 | 攻击动作与伤害事件配对差集 | 服务端自维护 `meleeMissCount` | 命中但被护盾抵消仍算命中 |
| 收锤 | 自上次攻击到冷却重新满的间隔 | 冷却进度 0→1 的时长 | 冷却进度差，不额外起计时器 | 不与「前摇」各起一套计时 |
| 攻击间隔 | 两次可造成伤害的攻击之间的最短时间 | `1 / 有效攻速` | `ATTACK_SPEED` modifier | 不得用调度器自行限流 |
| 前摇 | 发起到伤害判定的间隔 | 1.21 无该属性；**并入攻击冷却**，视觉用粒子 / 动画 | 与「攻击间隔」同一套数值 | 不得新增第二套冷却 |
| 攻速 | 每秒可完成的满蓄力攻击次数 | 基础 **0.6**（原生重锤，冷却约 1.67 秒），修正求和后 clamp ±30% | `ATTACK_SPEED` + `EquipmentSlotGroup.MAINHAND` | 不得逐条附魔各写一个 modifier |
| 冲刺 | 疾跑状态 | `Player#isSprinting()` | 原版疾跑 | 与 1.9+「冲刺攻击 / 暴击」区分 |
| 站定 | 连续 N 秒内位移小于阈值 | 位置采样，0.1 格 / tick | `PlayerMoveEvent` 或位置快照 | 不得以「未按键」代替 |
| 落点 | 重击命中时目标脚下的地面坐标 | 目标位置向下取整 | `Location` + 方块坐标 | 不得用玩家视线终点 |

**术语关系**：`收锤`（冷却期）→ `满蓄力` → 玩家发起 `重击`；`命中` 则结算附魔，`挥空` 则累加 `meleeMissCount`。23 / 51 / 65 / 73 / 95 五条全部折算到同一个 `ATTACK_SPEED` 修正值，求和后统一 clamp。

### 5.2 生命与资源术语

| 术语 | 定义 | 备注 |
| --- | --- | --- |
| 生命值 | 玩家血量，单位 ❤ | 回复 / 吸收 / 掉血均指此项，**不改变物品耐久** |

### 5.3 数值口径

| 单位 | 口径 | 示例 |
| --- | --- | --- |
| 百分比 `+X%` | **加法**并入伤害 / 减伤修正池，最后统一 clamp | `+6% / +9% / +12%` 指 tier 1 / 2 / 3 三档，非叠加 |
| 物品阶 `tier 1 / 2 / 3` | 决定附魔抽取池、`maxLive`、季节掉率；物品名显示 I / II / III 阶 | `IMythicItem.java:104-108`；`EnchantButton.java:310-312` |
| 附魔等级 `level 1 / 2 / 3` | 单条附魔的等级，与物品阶独立；由 `getMaxEnchantLevel` 限制 | 词条 lore 以 `RomanUtil.convert(level)` 显示（≥2 才显示），见 `AbstractPitItem.java:59-61` |
| ❤ | 半颗心 = 1 点生命值 | `0.5 ❤` = 1 点 |
| 秒 | 20 tick = 1 秒 | `2 / 3 / 4 秒` |
| 格 | 方块边长，欧氏距离 | `2 格` = 半径 2 的球形范围 |
| 点 `live` | 整数 | 消耗与回复均 clamp |
| 硬币 | 走 `PitGainCoinsEvent` | 56 铁账终值 5 / 10 / 15 |
| 冷却 | 自触发时刻起算，冷却中不重复触发、不重复扣 `live` | — |

**物品阶适配列统一读法**：`a / b / c` = tier 1 / 2 / 3 各自数值；「仅 tier 3」= 只在 tier 3 池出现。列中须列出**所有**随物品阶变化的主数值；效果概述可用完整句子复述同一组数值，但不得出现列中未列出的随阶数值（P5 通则）。

> **术语铁律**：正文一律用 `tier N` / `level N`；`I / II / III` 仅用于描述物品名与词条 lore 的**显示文本**，不作为术语指代。

### 8.3 Q4 全开语义（原 Q12 裁定）

- **10—12 月全 10 条是需求硬性指定的年度复刻窗口，不是笔误**。前三季度是**首放窗口**，Q4 是**年度复刻窗口**。

- 「清单无重复」指 100 条清单内编号唯一；「月份安排无矛盾」指月份区间不重叠。两者与跨季度重复开放无关。
- 去重编号数为 10；3 + 3 + 4 + 10 = 20 是「季度 × 条目」出现次数，属另一口径，不参与校验。
